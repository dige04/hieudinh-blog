# CLIProxyAPI Render Deployment

Deploy CLIProxyAPI as a Docker web service on Render.com free tier.

## Architecture

```
Client (ANTHROPIC_BASE_URL)
  |
  v
Render Edge (HTTPS, port 443)
  |
  v
CLIProxyAPI container (port $PORT)
  |--- config.yaml (generated at startup from template + env vars)
  |--- /root/.cli-proxy-api/ (auth files decoded from AUTH_FILES_B64)
  |
  v
Upstream AI providers (Anthropic, Google, OpenAI, etc.)
```

## Files

| File | Purpose |
|------|---------|
| `Dockerfile` | Wraps `eceasy/cli-proxy-api:latest` with startup scripts |
| `entrypoint.sh` | Decodes auth files, generates config, starts the binary |
| `config.template.yaml` | Config template with placeholder values |
| `render.yaml` | Render blueprint for infrastructure-as-code deployment |
| `sync-auth.sh` | Script to push local auth files to Render |
| `.dockerignore` | Excludes non-build files from Docker context |

## Deployment Steps

### 1. Initial Setup on Render Dashboard

1. Go to https://dashboard.render.com
2. New > Web Service
3. Connect your GitHub repo (my-portfolio)
4. Configure:
   - **Name**: `cliproxyapi`
   - **Region**: Oregon (US West)
   - **Runtime**: Docker
   - **Dockerfile Path**: `infra/render-cliproxyapi/Dockerfile`
   - **Docker Context**: `infra/render-cliproxyapi`
   - **Plan**: Free
   - **Health Check Path**: `/v1/models`

### 2. Set Environment Variables

In the Render dashboard, go to your service > Environment:

| Variable | Value | Notes |
|----------|-------|-------|
| `CLIPROXY_API_KEYS` | `your-key-1,your-key-2` | Comma-separated client API keys |
| `AUTH_FILES_B64` | *(generated by sync-auth.sh)* | Base64 tar.gz of auth files |
| `CLIPROXY_REQUEST_RETRY` | `3` | Optional, default 3 |
| `CLIPROXY_ROUTING_STRATEGY` | `round-robin` | Optional |
| `CLIPROXY_NONSTREAM_KEEPALIVE` | `30` | Prevents Render idle timeout |
| `CLIPROXY_DEBUG` | `false` | Optional |

### 3. Upload Auth Files

Generate and set the AUTH_FILES_B64 value:

```bash
# Option A: Use the sync script (requires RENDER_API_KEY)
export RENDER_API_KEY="rnd_xxxxx"
./infra/render-cliproxyapi/sync-auth.sh

# Option B: Generate value and paste manually in dashboard
./infra/render-cliproxyapi/sync-auth.sh --encode-only | pbcopy
# Then paste in Render dashboard > Environment > AUTH_FILES_B64
```

### 4. Use as ANTHROPIC_BASE_URL

Once deployed, your service URL will be:
```
https://cliproxyapi.onrender.com
```

Set it as your proxy:
```bash
export ANTHROPIC_BASE_URL=https://cliproxyapi.onrender.com
export ANTHROPIC_API_KEY=your-cliproxy-api-key
```

## Auth File Sync

When auth tokens are refreshed locally, push them to Render:

```bash
# Full sync (update env var + trigger redeploy)
./infra/render-cliproxyapi/sync-auth.sh

# Preview what would be uploaded
./infra/render-cliproxyapi/sync-auth.sh --dry-run

# Just get the base64 value
./infra/render-cliproxyapi/sync-auth.sh --encode-only
```

### Automated Sync (Optional)

Add to crontab to sync daily:
```bash
# Sync auth files to Render every 6 hours
0 */6 * * * RENDER_API_KEY=rnd_xxx /path/to/sync-auth.sh >> /tmp/sync-auth.log 2>&1
```

## Free Tier Limitations

| Constraint | Impact | Mitigation |
|------------|--------|------------|
| Sleeps after 15min idle | First request takes ~30s | Use uptime monitor (e.g., UptimeRobot) |
| 512MB RAM | May OOM under heavy load | `commercial-mode: true` in config |
| No persistent disk | Auth files lost on restart | Injected from env var at startup |
| 750 hours/month | Enough for 1 service 24/7 | Only deploy one free tier service |
| Outbound bandwidth limit | May hit limits with heavy use | Monitor usage |

## Local Testing

```bash
cd infra/render-cliproxyapi

# Build the image
docker build -t cliproxyapi-render .

# Run with local auth files mounted (simulates Render)
docker run -it --rm \
  -p 8317:8317 \
  -e PORT=8317 \
  -e CLIPROXY_API_KEYS="test-key-1" \
  -e AUTH_FILES_B64="$(tar czf - -C ~/.cli-proxy-api . | base64)" \
  cliproxyapi-render

# Test health check
curl http://localhost:8317/v1/models
```

## Troubleshooting

**Service won't start**: Check Render logs. Common issues:
- AUTH_FILES_B64 not set or malformed
- Port binding conflict (ensure no hardcoded port in config)

**Auth errors from upstream**: Auth tokens may have expired.
Run `sync-auth.sh` to push fresh tokens.

**Timeout on long requests**: Render free tier has a 100-second
request timeout. The `streaming.keepalive-seconds: 15` config
helps keep connections alive during streaming responses.

**502 Bad Gateway after sleep**: The first request after idle
wakes the service. Wait ~30s and retry.
